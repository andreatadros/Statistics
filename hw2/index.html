Part 1 — Toy elliptic curve and public-key scheme

We work on the toy curve y² = x³ + 7 (mod 17), the same shape as Ethereum's secp256k1 (y² = x³ + 7) but over a tiny field so every computation can be done by hand. The base point is G = (1, 5).

Scalar multiplication Q = k·G (adding G to itself k times) is the one-way function: easy to compute forward, hard to invert. The private key is the secret scalar k; the public key is the point Q.

All multiples of G (the cyclic group generated by G)



The number of distinct points (plus the point at infinity) is the
order n of G. A private key is any scalar in 1 … n−1.

Encryption / decryption on the toy curve




We use a textbook ElGamal-on-EC scheme. A message is first mapped
to a curve point M. With recipient private key d and public
key P = d·G:


    

  • Encrypt: pick a random scalar r, send the pair
(C1, C2) = (r·G, M + r·P).
    • 

  • Decrypt: compute C2 − d·C1 = M, because
d·C1 = d·r·G = r·P.
    • 



Here the plaintext is a single letter, mapped to a small multiple of G so it lands
on a real curve point.








Part 2 — The Caesar cipher




The Caesar cipher shifts every letter by a fixed amount s (the key), with
c = (m + s) mod 26 and m = (c − s) mod 26. The key space is
tiny: only 26 possible shifts (25 useful ones).

Key point: Caesar preserves the letter-frequency distribution — it
only relabels letters — which is exactly the weakness the next section exploits. The
ECC scheme hides it, but here its key space is small enough to brute-force.






Part 3 — Statistical cryptanalysis of Caesar




English has a very skewed letter distribution (E, T, A, O… are common; Z, Q, X rare).
A Caesar shift moves that whole distribution sideways. To break it we try all 25 shifts
and pick the one whose decrypted letter frequencies best match English — using
chi-squared against reference English frequencies. The smallest χ² wins.

As the table shows, the attack is reliable on long texts and

Part 4 — Attacking the restricted ECC key space




Our toy scheme restricts the private key to a small range, so we can just
try every candidate: for each k, compute k·G and check whether it
equals the public key Q. This is a brute-force / exhaustive search.




Why this differs from the Caesar attack


    

  • The Caesar attack is statistical: it exploits structure left in the
ciphertext (letter frequencies). It needs no key search — it reads the key off the data.
    • 

  • The ECC attack is a pure key search: the ciphertext leaks no usable
statistics (r randomises it), so we attack the small key space instead.
    • 



Why it fails on real ECC


secp256k1 uses a private key up to ~2²⁵⁶. Brute force would need on the order of
10⁷⁷ scalar multiplications — physically impossible. There is no known attack that reads
the key from the ciphertext either, because scalar multiplication destroys the kind of
statistical structure that frequency analysis relies on. The weakness here is
entirely the restricted key space, not the scheme's design: widen the
key range and the same brute force becomes hopeless.
